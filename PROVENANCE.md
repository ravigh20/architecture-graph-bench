# Input provenance and scientific boundaries

## Source of this release

This update builds on the supplied demo-enabled implementation. It retains the Boutique source/reference files, four manifest bundles and frozen backend references, and their source, field and license records unchanged. The 17-system archived reference/raw-output dataset is restored from the earlier `AGB_All_Evidence.zip`, with a separate projection of the source study's annotated connections added for the submission candidate.

`data/input_manifest.json` records each input's role, bytes and SHA-256. `data/experiment_config.json` describes the four diagnostic policies, thresholds, weighting schemes, four-application membership evaluation and held-out proposal calibration. Parameters are not measured results. The experiment configuration and input inventory were updated; original YAML, reference labels, raw retained records and source metadata were not edited to obtain a score.

## Online Boutique

The working YAML is the retained 978-line transcription associated with v0.10.3 / commit `cd1cb59f6fce3e2ccf08be7cea743e3784932d73`. Its bytes differ from the separately retained upstream candidate. Processing writes a byte-difference file and a scored-field comparison. Both are local-copy checks, not a new upstream acquisition or independent source authentication.

## Backend labels and model record

Bookinfo and the three fitting datasets use previously supplied model-assisted backend references. Source-located witnesses are recalculated from the retained manifests. They are not newly collected independent human annotations.

`data/study/llm/bookinfo.json` is the preserved structured prediction from the previous package. It contains the backend sets needed for re-scoring, not a full API request/response session, dated model snapshot, seed, or sampling settings. Those unavailable historical records are not invented. The earlier focused paper described one saved model response. It remains available in the optional legacy Bookinfo check, but the current submission-candidate default workflow does not use it as an experimental method. Section II's external LLM aggregate results are related work, not new predictions generated by this package.

## Optional reference candidate

The Boutique builder joins source records through a separately written code path, retains locations, calculates query labels and emits pending review tasks. It shares the declared interpretation rules with M2. Separate implementation and identical output do not establish independence or scientific correctness.

## Limits

No cluster is deployed. No packet traffic, policy enforcement, new tool/model runs, reviewer agreement, annotation time, full provenance entailment, five-class accuracy or practitioner benefit is measured by this package. The final paper marks these as limits/further evaluation. No completed evidence is fabricated for them.

Table I is the manuscript's related-work characterization, not an independent literature audit by this implementation. Figures 1–5 are illustrations, not measurements.

# Submission-candidate update: archived connection inputs

The replay now uses the paper's source-study-annotated TP/FP connections, not the earlier raw-only evaluation as its main result. Source: Schneider et al., EMSE2025SAR-Replication v1.1, DOI `10.5281/zenodo.14978488`.

`data/replay/annotated_connections.json` contains 27 records with the source URL, source version, original connection label/text and one-based upstream line locator. The connection sections and identified FP arrows were transcribed from browser-retrieved raw source text during this update. This is **not a byte-identical download of the upstream archive**. The full archive download could not be obtained in the execution environment. FN records are retained but not placed in predictions. Non-connection component/endpoint annotations are not fabricated as connection data.

The existing 17 textual reference graphs, raw JSON/SVG predictions and component-only alignment projections were recovered unchanged from the earlier AGB evidence package. Their existing `inputs_manifest.json` and `offline_inputs.json` record their original upstream and retained checksums. The raw inputs are associated with source commit `1b8994471e9df0d32e22b31415eead8511078125`; byte equivalence to every v1.1 upstream raw file has not been independently reacquired in this update.

`tools/verify_replay_sources.py` can check the connection projection against a locally extracted full archive, or fetch the 27 pinned-version text files into a separate output directory. It does not rewrite experiment inputs. A local hash verifies consistency of the retained representation, not source authenticity or annotation correctness.

Raw sensitivity uses two explicit alternatives: spelling normalization alone, and the same normalization plus published component aliases. Both preserve raw arrow directions, self-loops and extra endpoints. Their probability models are refitted on their own raw proposal populations. The raw .95 statement in the paper does not reproduce with these retained inputs/conventions; consult the release verification report.

The final submission workflow does not evaluate new LLM outputs. Related-work LLM aggregate scores in Section II are not copied into an experiment or represented as this project's own model runs.
